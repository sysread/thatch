# Nomenclater

## Synopsis

Assigns a geeky/sci-fi name to the agent at the start of each new opencode
session. The name is generated by a fast LLM call, cached for the session, and
injected into the system prompt so the agent knows its name. opencode-only;
requires plugin hooks. Pure cosmetic, no functional dependency.

## Background

Fnord's Nomenclater (backed by a GenServer name pool) generates whimsical names
for sub-agents so their actions are distinguishable in logs. Jeff explicitly
wants this for thatch: "I'd love to have this!" It builds agent identity and
rapport, complementing the personality instructions in OPENCODE.md.

The name must not change mid-conversation and must not trigger on continued
or resumed sessions.

## Session detection

Same mechanism as the intuition-drives plan. See that plan for full detail.

`session.created` fires only on brand-new session creation (fresh or fork). It
does not fire when resuming an existing conversation. Detection: track
`session.created` for top-level sessions (no `parentID`) in a `Set<string>`,
generate the name on first `chat.message` for sessions in that set, remove
from set after generating. Continued/resumed sessions never enter the set.

## What it does

```
session.created (top-level) → add sessionID to newSessions Set

chat.message (first message for sessionID in newSessions)
  → remove from newSessions
  → generate name via fast model → cache in Map<sessionID, name>

experimental.chat.system.transform
  → if name cached for sessionID: append "Your name for this session is <name>."

session.deleted
  → delete from name cache, newSessions set
```

Name generation uses fnord's theme list (Jargon File, Zork, Futurama,
Discworld, D&D, Klingons, Sandman, etc.) and the same JSON-schema response
format. One LLM call with a fast model. Themes are shuffled and 3 are selected
per batch to avoid clustering.

## Constraints

- **opencode-only.** Requires plugin hook injection. The name is generated by a
  fast LLM call and injected via `experimental.chat.system.transform`.
- **First-message-only.** Same session-detection mechanism. The name must not
  change mid-conversation.
- **No persistent state needed.** The name is generated fresh per session and
  held in a per-session map for the duration of that session. No DB writes.
- **Must not trigger on continued sessions.** A resumed conversation keeps
  whatever name the agent had (or had none, if the feature was added after the
  session started). The `session.created` gate handles this.

## Open question

1. **Where does the name surface?** System prompt injection means the agent
   knows its name but the user only sees it if the agent chooses to use it. Is
   that enough, or should the name appear in the TUI somehow (e.g., a toast on
   session start)?

## Decisions

| Decision | Rationale |
|----------|-----------|
| opencode-only | Requires plugin hooks for generation and injection |
| One name per session, cached in memory | No DB writes; name is ephemeral, tied to session lifecycle |
| Gated to first message of new sessions | Must not rename mid-conversation or trigger on resumed sessions |
| Detection via session.created + chat.message | Same mechanism as the intuition-drives plan |

## Dependencies

### Runtime

- Fast model for name generation (one LLM call per new session)

### Built-in

- Plugin hooks: `event` (session.created, session.deleted),
  `chat.message`, `experimental.chat.system.transform`
- In-process `Map` for per-session name caching
